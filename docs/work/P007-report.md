# P007 report — why Maven Central was unreachable

## Cause

**Norton 360 for Gamers (Web/Mail Shield) scans TLS traffic.** It replaces each server's certificate with one it
signs itself. Windows trusts Norton's root, but Java does not.

| Check | Result |
|---|---|
| `mvn -U -DskipTests dependency:resolve` (online) | Fails: `(certificate_unknown) PKIX path building failed: … unable to find valid certification path to requested target`, for every artifact from `https://repo.maven.apache.org/maven2` |
| Certificate the machine receives for `repo.maven.apache.org` | Subject `CN=repo.maven.apache.org`. Issuer **`CN=Norton Web/Mail Shield Root, O=Norton Web/Mail Shield, OU=generated by Norton Antivirus for SSL/TLS scanning`** |
| Windows trust | Chain valid (HTTP 200). The Norton root (thumbprint `6C19EAE5…9A46`, valid to 2040) is in `LocalMachine\Root` and `CurrentUser\Root` |
| Java trust | The Norton root is **not** in the JDK's `cacerts` (Temurin 21.0.13, 118 entries) |
| Maven `settings.xml` | None (`~/.m2/settings.xml` does not exist; no mirrors or proxies) |
| `HTTPS_PROXY` / `HTTP_PROXY` / `MAVEN_OPTS` / `JAVA_TOOL_OPTIONS` | Not set |
| Windows proxy | WinHTTP: direct access. Internet settings: proxy off, no auto-config script |
| Antivirus | Norton 360 for Gamers (active), Windows Defender |

There is no proxy or VPN. Java sees a certificate from an issuer it does not know and refuses the connection, which
is the correct behaviour.

## What was changed

- New file **`.mvn/jvm.config`** with one line: `-Djavax.net.ssl.trustStoreType=Windows-ROOT`. Maven's own JVM now
  checks certificates against the Windows trust store, which holds the normal public roots and the Norton root.
  Certificate checking stays fully on.
- Nothing else. No change to Windows, the JDK, `cacerts`, Norton or `~/.m2`. No insecure flags.
- The file applies to Maven's JVM only, not to the forked test JVMs. The tests make no outside TLS connections.

## Online build

- `mvn -U -DskipTests dependency:resolve`: **success**, 159 artifacts downloaded from Central, no PKIX errors.
- `mvn -U clean verify` (online): **BUILD SUCCESS, 283 tests, 0 failures, 0 errors** (identity-core 73,
  identity-spring 15, notifications 65, notifications-testkit 101, notifications-spring 29).
- From now on the build no longer needs `-o`.

## LexaVault and SDV

**Yes, on this machine.** Neither has a `.mvn/jvm.config` today, and every Maven build here goes through Norton. Add
the same file next to each top-level `pom.xml` that is built:

- `C:\dev\lexavault\secure-document-platform\backend\.mvn\jvm.config`
- `C:\dev\lexavault\sdp-ui\backend\.mvn\jvm.config` (if that backend is built with Maven)
- `C:\dev\sdv\secure-document-vault\backend\.mvn\jvm.config`

Maven looks for `.mvn` in the folder of the project being built and in the folders above it. The file can go in the
`backend` folder or in the repo root above it. Those repos were not changed in this task.

**Caution:** the `Windows-ROOT` store exists only on Windows. On a Linux or macOS machine, or in a Linux CI
container, Maven would fail at its first download with this file in place. None of these repos has CI today. If a
non-Windows build is added, do one of these instead:

- import the Norton root into that machine's trust store (only where Norton is installed), or
- turn off Norton's encrypted-connection scanning for `repo.maven.apache.org`, or
- set the option per machine in `MAVEN_OPTS` and not in the repo.

Each of these is a system or antivirus change, so each is for the owner to decide.
